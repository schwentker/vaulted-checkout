# Contract changelog

- 2026-10-25 CX-1 clarification (Claude/Robert, applied by Codex): adapter results are a tagged union. list_products returns {status:'ok',products}; create_order returns {status:'created',...order}; get_order returns {status:'order',...order,payment?}. Payment variants are {status:'settled',orderId,amount,txHash,explorer}, {status:'refused',orderId,code,reason}, and {status:'pending',orderId,state,hint}; errors are {status:'error',code}. Acceptance now requires the exact fixed discriminator on each result variant and rejects unknown or wrong-variant tags. Product and line-item records retain their prior field allowlists. This supersedes the untagged adapter description in the initial CX-1 handoff. All non-discriminator assertions remain; the frozen event schema and theater evaluator are unchanged. Claude Code must conform to these tags, including nested get_order payment objects.

- 2026-10-25 CX-1 (Codex): events v1 added in contracts/events.schema.json for the shared replay JSONL. Only t, actor, kind, orderId, productId, amount, code, and txHash are allowed. Order events require orderId; settled requires decimal USDC amount and a full txHash; refused requires code; only settled can carry txHash. Stream timestamps must be nondecreasing. Existing payment contracts remain v1.1. Claude Code and Argon must conform to this schema and the snapshot binding/timing rules in theater/eval/README.md. The schema is included in FROZEN.sha256; do not change it during evaluation repair. Gate B fixture provenance and remaining adapter blocker are in docs/handoff/cx-1.md.
