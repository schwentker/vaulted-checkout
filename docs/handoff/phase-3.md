## What is done
- Signer Reactor. `reactors/signer/main.js` is the body; `reactors/signer/reactor.js` is generated by `scripts/build-signer.mjs` from the **v1.1** `contracts/reference/intent-core.cjs` + main.js (one file, as BT requires). `--check` fails if reactor.js is stale. Flow: shape (400) then MAC (401) then hard rules from configuration (403, or 400 for malformed) then key retrieval with runtime `token:read`+`token:reveal` (500 on any key problem) then wallet address match then EIP-712 TransferWithAuthorization sign then `{ok, from, signature, attempt_id}`. Request fields never feed rules. No logging. The key is fetched only after every rule passes.
